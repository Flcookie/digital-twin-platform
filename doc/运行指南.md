# LEGO Factory 运行指南

> **Web 仪表盘已改为 Streamlit**（默认 <http://localhost:8501>）。若下文仍出现 `uvicorn`、`localhost:8000` 或旧版 `web_api`，请改为：`run_web.bat` / `python -m streamlit run streamlit_app/app.py`。

## 一、前置条件

### 1. 环境要求

- **Python 3.10+**
- **MQTT Broker**：物理系统需已连接并运行；本地测试使用 broker.hivemq.com
- **Neo4j**：若需 Part Flow 和流程图，需本地或远程运行 Neo4j

### 2. 安装依赖

```powershell
cd c:\Users\beira\lego-factory

# 创建虚拟环境（首次）
python -m venv .venv

# 激活虚拟环境
.venv\Scripts\activate

# 安装依赖
pip install -r requirements.txt
```

### 3. 配置文件

确保项目根目录有 `config.json` 或 `config_local.json`，其中需包含：

- `mqtt_broker_host`：MQTT 地址（本地测试用 broker.hivemq.com）
- `mqtt_broker_port`：通常 1883
- `neo4j`：若用 Neo4j，需配置 uri、username、password

**敏感信息（可选）**：密码等可放在 `.env` 中，参考 `.env.example`。环境变量 `NEO4J_PASSWORD`、`SSH_PASSWORD` 会覆盖 config 中的值。

## 四、仪表盘功能说明

### 4.1 Historical Log Replay（历史 Log 模拟）

- **Upload & Replay**：选择 CSV、设置倍速（1=实时，10=10 倍速）后点击，自动启动 main_service 并开始模拟
- **Stop Replay**：模拟进行中显示，点击暂停
- **Reset**：清空 KPI/图表/Part Flow，可上传新文件
- **Stop main_service**：停止由 Dashboard 启动的 main_service

### 4.2 物理系统控制按钮（按流程顺序）

| 步骤 | 按钮 | 功能 |
|------|------|------|
| 0 | **Upload Code** | 将本地 Python 代码通过 SSH+SFTP 部署到各控制器（代码修改后使用） |
| 0 | **Upload Config** | 将本地配置文件部署到各控制器（参数调整后使用） |
| 1 | **Start Programs** | SSH 到各控制器，启动组件程序（corner、driver、splitter、station 等） |
| 2 | **Start main_service** | 启动主服务（MQTT→Neo4j+KPI），**必须先于 Start System 运行** |
| 3 | **Start System** | 发布 component_wip、system_time、system_status=START |
| 4 | **Start Record** | 开始监听 MQTT 事件，实时写入 CSV |
| 4 | **Stop Record** | 停止监听，保存 CSV 文件 |
| 5 | **Stop System** | 发布 system_status=STOP |
| 6 | **Stop Programs** | SSH 到各控制器，停止组件程序 |
| 7 | **Shut Down** | 关闭所有控制器和 broker |

**辅助按钮：**
- **Reset All**：开始新 Session + 重置 KPI（历史数据保留，便于多次运行对比）。Session 描述输入框支持下拉建议（Baseline run、Test run 等）

**说明**：Upload Code/Config 后需 Stop Programs → Start Programs 才能生效。物理系统需在 `config.json` 中配置 `local_code_paths` 和 `local_config_paths`（`config_local.json` 通常为空，用于本地测试）。

### 4.3 KPI 卡片

- **Throughput**：吞吐量（parts/s）
- **Finished**：完成件数
- **Scrap**：报废件数
- **WIP**：在制品数量
- **Obs Time**：观测时间（秒）
- **Avg Flow Time**：平均流时（秒）

### 4.4 图表

- 吞吐量随时间变化
- WIP 随时间变化

### 4.5 工位状态

显示各工位利用率及六种状态占比（Loading、Blocked、Idle、Processing、Unloading、Failed）。

### 4.6 Part Flow

- 展示每个零件在装配线上的流转路径，含工位与活动（如 p12: corner2@START → station11@LOAD → station11@PROCESS → ...）
- 仅显示**当前 Session** 的数据（Session 分离，便于多次运行对比）

### 4.7 Session 与数据保留

- 每次 main_service 启动或点击 Reset All 会创建新 Session
- Neo4j 中历史 Session 数据保留，Part Flow 仅显示当前 Session
- 需清空 Neo4j 全部数据时，请在 Neo4j 数据库中手动删除

### 4.8 MQTT 状态

- 页面顶部 header 显示 **MQTT: ● Connected** / **○ Disconnected**，便于排查 KPI 无数据问题

## 五、完整工作流（含物理系统）

若连接真实 LEGO 工厂（Multi-Loop 等）：

1. **连接 Wi-Fi**（如 THE FACTORY - ROUTER 3）
2. **打开 MobaXterm 会话**：corner、driver、splitter、station 等
3. **在各会话中运行组件程序**（如 `python3 corner.py`）
4. **启动主服务**：`run_main.bat` 或 `python main_service.py`
5. **启动仪表盘**：`run_web.bat`（**Streamlit**，默认 **http://localhost:8501**）
6. **在仪表盘点击 Start System**，或运行 `python start_system.py`
7. 观察 KPI、Part Flow 和工位状态
8. 结束时点击 **Stop System**，或运行 `python stop_system.py`

## 六、启动 Streamlit 仪表盘

### 6.1 推荐方式

**方式一：双击 `run_web.bat`**

**方式二：终端手动启动**

```powershell
cd c:\Users\beira\lego-factory
.\.venv\Scripts\Activate.ps1
$env:CONFIG_FILE = "config.json"
python -m streamlit run streamlit_app\app.py
```

浏览器访问 **http://localhost:8501**（不要用 `file://`）。

### 6.2 与 main_service 的关系

- **形态 B**：先起 `main_service.py`（或在 Streamlit **Control** 页启动），再起 Streamlit；二者共用 `CONFIG_FILE` 指向的 MQTT/Neo4j。
- Streamlit **不会**替代 `main_service` 写库与算 KPI。

### 6.3 端口占用

**查看占用 8501 的进程：**

```powershell
netstat -ano | findstr ":8501"
```

若 8501 被占用，可运行 **`run_web_8001.bat`**（Streamlit `--server.port 8502`），访问 **http://localhost:8502**。

### 6.4 手动 Kill 进程

| 操作 | 命令 | 说明 |
|------|------|------|
| 结束所有 Python | `taskkill /F /IM python.exe` | 会关闭 Streamlit、main_service 等 |
| 结束指定 PID | `taskkill /F /PID <pid>` | 先用 `netstat` 查 PID |

## 七、常见问题（FAQ）

**Q: 必须手动运行 run_web.bat 吗？**  
A: 是的。仪表盘为 Streamlit，需启动后浏览器打开 **http://localhost:8501**，在左侧 Pages 中切换实时 / 历史 / 控制等。

**Q: 仪表盘无数据？**  
A: 历史 Log 模式：确认已点击 Upload & Replay。物理系统模式：确认 main_service 已运行。查看 header 中 MQTT 状态（● Connected 表示正常），检查 `config.json` 中 `mqtt_broker_host`。

**Q: MQTT 连接失败？**  
A: 若 broker 在远程（如 `broker` 主机），需确保网络可达。本地测试可将 `mqtt_broker_host` 改为 `localhost` 并启动本地 broker。

**Q: 端口 8501 被占用或打不开？**  
A: 用 `netstat` 查占用进程并结束，或改用 **`run_web_8001.bat`** 访问 **http://localhost:8502**。

**Q: 页面一直转圈加载？**  
A: 确认终端里 Streamlit 无报错；刷新浏览器；必要时更换端口启动。
